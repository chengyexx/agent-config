# Artifact Reconciliation —— 设计"真能发现问题"的验收

写验收判据、验收脚本、门禁、数据完整性 / 一致性核对，以及判断**一条已有判据够不够格**进门禁。
纯粹答疑、一次性肉眼检查不走此流程。

**目录**：0 判定 · 1 核心 · 2 强度轴 · 3 硬规则 · 4 结构 · 5 判据写法 ·
6 判据模式 · 7 门禁清单 · 8 FAIL 归因 · 9 反模式 · 10 工作流 · 11 实例

## 0. 判定

- 只查一次、不打算复用 → 直接看，别建框架。
- 要写进门禁 / 要被反复跑 / 要交给人验收 → 走完整流程。

## 1. 核心：验收 = 独立对账

> **验收 = 一组「产物 A vs 产物 B」的独立对账程序。**

- 判据必须由**两个互相独立**的东西比出来；不能是产物跟它自己的上游比（同源必然自洽，必过）。
- 不生成方案投票，不做 AI 交叉评审。**独立性来自判据，不来自模型个数**：同一个模型写实现又写测试，会共享同一片盲点。

出处（**只引原始论文，不引二手转述**）：

- **同源 → 互相掩盖**：实现之后补写的测试只检出 **14%** 缺陷，独立于实现生成的检出 **25%**（[arXiv 2607.05139](https://arxiv.org/abs/2607.05139)，5 模型 / 3 基准，全部显著；CoT 无法缓解）。
- **被错误实现误导**：真实代码上，针对错误实现生成的测试**检出率低 47%**；把"自然语言的正确行为描述"加回去**恢复 +34%**（ICSE 2026，[arXiv 2409.09464](https://arxiv.org/abs/2409.09464)）。
- **规格 grounding 比"多写测试"更有效**：+38pp，且无规格的生成器会**发明规格**（假警报 33% vs grounded 0%）（[arXiv 2607.06636](https://arxiv.org/abs/2607.06636)）。

（这些结论被一个低关注度的聚合仓库转述过；**框架借它的命名，数字一律回原始论文核**。）

## 2. 两条强度轴

**轴一：对齐粒度（拿什么比）**

| 级别 | 查什么 | 能发现的漏 | 能否当验收 |
|---|---|---|---|
| L1 存在性 | A 里有的，B 里有没有 | 整条丢失 | ❌ 只能当索引 |
| L2 计数守恒 | `count(A) == count(B)` | 成批丢失 | ⚠️ 不够 |
| L3 逐条对齐 | 每条能一对一找到（多重集，含重复次数） | 部分丢失、错配 | ✅ 内容最低要求 |
| L4 归属正确 | 挂在正确的父对象上 | 挂错 | ✅ |
| L5 约束有效 | 唯一键 / 外键 / 非空真的在起作用 | 约定形同虚设 | ✅ |
| L6 扫描报警 | 未登记类型、死列、异常分布 | 你没想到的 | ✅ 部分覆盖 |

**轴二：证据强度（这条判据本身可信吗）**

| 级别 | 查什么 | 为什么需要 |
|---|---|---|
| L7 变异可检 | 把**已知缺陷**注入产物，判据必须变红 | 否则"检查过了"只是"没报错"；这是**进门禁的最低要求** |
| L8 关系守恒 | 没有标准答案时，声明"必须成立的关系"，在变换后仍成立 | 无绝对 oracle 的场景（排序质量、语义召回、模型输出） |

> L7 是**判据的必要性自检**（"它真的会红吗"），**不是**"变异分能代表质量"。代理指标（覆盖率 / 变异分）与真实缺陷检出的相关性**依赖场景**：被测物被假定无错、只看回归时它们有意义；被测物本身可能有错时不可靠（[arXiv 2607.22880](https://arxiv.org/abs/2607.22880) 的复现研究）；变异测试在高成本场景的增益也被质疑（[arXiv 2609.09315](https://arxiv.org/abs/2609.09315)）。**所以别设变异分 / 覆盖率阈值**。

**硬规则**
1. 内容对齐**至少 L3**。
2. **进门禁的判据必须做到 L7**，且"会红"这件事要固化成可复跑的形式（如 `--self-test`），不是口头声明。
3. 有绝对答案走 L3+；没有就走 L8。**不许**退化成"看着没问题"。

## 3. 对账程序的 6 条硬规则

1. **不调用 LLM 做判定**。模型可以作为**被测系统**或**输入生成器**，但"通过 / 不通过"必须由确定性代码算出。
2. **不 import 生产代码的判定函数** —— 会复制同一个 bug。而且这条要**机械校验**，不能靠自觉（见 §7 G1）。
3. 只读产物（文件 / DB），不读"生成它的那个输入"。
4. 输出 exit code + 可读清单，能进 CI。
5. **先在能复现问题的最小数据上证明它会 FAIL**，再拿去用（= L7）。
6. **放水等于改判据**：放宽比较、跳过、删断言、收窄生成域、改 fixture，一律视同修改验收标准 —— 必须留痕并复核。

## 4. 结构：AI 只占一层

```
人（终审）                        ← 主观取舍
1 个 AI（单线程，不派子 agent）    ← 写程序、跑程序、改代码
对账程序（不是 AI）               ← 主体
```

升级规则（满足才加，不要默认开）：

| 触发条件 | 动作 |
|---|---|
| 判据全 PASS 但人工打回 | 加一个**换模型族**的对手（同模型换 prompt 没用） |
| 出现未登记的新类型 | 先补登记 + 补判据，不是先加 agent |
| 需要发散出候选方案 | 才考虑多 agent，N ≤ 3–5，必须异构 |

> "单 agent 基线超 45% 后多 agent 零到负收益 / 独立拓扑放大误差 17 倍" 属**经验值，无强证据**，别当定理用。真正的依据是上面那条：同模型共享盲点。

## 5. 判据写法

| ❌ 不是判据 | ✅ 是判据 |
|---|---|
| 「引用完整」 | 「每个 doc 内，`chunks` 里 `(token,anchor,kind)` 的**多重集** == 边表该 doc 的多重集」 |
| 「数据无损」 | 「`X.title` 经 JOIN 后与源 `X.title` 逐字段相等」 |
| 「幂等」 | 「连导两次，各表**主键集合**完全相同」 |
| 「注释齐全」 | 「DDL 文件与 `information_schema` **双向逐项**：多一个少一个、值不同都要报」 |
| 「索引一致」 | 「逐点 `chunk_id` 对齐且 payload `text` 全等，双向无多余 / 缺失点」（计数相等不够） |
| 「检查过了」 | 「做到 L3+，且注入已知缺陷会 FAIL（L7）」 |

## 6. 判据模式目录

按"要防什么漏"选。

### 6.1 逐条对齐（L3，默认起点）
防：部分丢失、错配、重复次数变化。
```
按自然键分组 → 两侧都算【多重集】→ 比较
问题清单 = 缺、多、值不同、次数不同（四类分开报）
```
- **多重集**不是集合：`Counter(A) == Counter(B)`，否则重复被吃掉。
- 四类分开报，不要合并成一条"不一致"——归因要用。
- 分组键按业务（按 doc / 按租户），不要全局一把梭。

### 6.2 双向（缺失 + 多余）
```
problems = [A 里有 B 没有] + [B 里有 A 没有]
```
只查一边，另一半的脏数据（陈旧点、孤儿行）永远看不见。
**构造夹具时必须同时造出"两边各缺一个"**，否则你以为双向覆盖了，其实只测了一半。

### 6.3 大产物：分桶计数 + 哈希
全量逐条在几千 / 几百万行时不可行。降级但**不降级到计数相等**：
```
每个分片（按 hash(key) % N 或按日期）→ {count, xor/sum(sha256(value))}
两侧按分片比；不一致的分片再逐条展开
```
- 哈希用**可交换聚合**（XOR / 求和）才与顺序无关。
- 分片只定位问题，**最终判定仍要展开到逐条**。

### 6.4 约束有效性（L5）
防：约束写了但不起作用（唯一键含恒 NULL 列、CHECK 被绕过、应用层"以为"有外键）。
**测法：主动制造违例，必须被拒。**
```
尝试插入：重复的自然键 / NULL 的必填列 / 越界值
期望：被拒（特定错误码）；若"成功"→ 约束形同虚设 → FAIL
```
必须在事务里做，跑完回滚。

### 6.5 扫描报警（L6）
不预设答案，扫全量后报**反常分布**：未登记的类型值、全 NULL 列、单一取值列、长度突变、时间戳倒挂、注释为空的表/列。
输出是 **warning**（见 §7 G4），不直接判死；每出现新的"未登记类型"，先补登记 + 补判据。

### 6.6 蜕变关系（L8）——没有标准答案时
排序 / 召回 / 模型输出这类东西，用"必须成立的关系"当部分 oracle。

| 关系 | 变换 | 期望 |
|---|---|---|
| 不变性 | 改写提问（同义）、打乱无关上下文 | 命中的对象不变或不变差 |
| 单调性 | 加更多相关上下文 / 提高 top_k | 命中率不下降 |
| 等价 | 重建派生索引 / 重跑同输入 | 派生物逐字段相同 |
| 可逆 | A→B→A 的往返 | 回到起点（如导出再导入） |
| 差分 | 两个独立实现 / 新旧实现 | 结果一致（不一致即有一方错） |

- **关系本身要被验证**（变换是否真的保持语义），否则会造假警报。
- 关系不成立给的是**证据**不是证明；结论要写明强度。

### 6.7 属性生成（L6 的进攻版）
用 property-based 思路随机 / 组合生成输入，跑"必须永远成立的性质"（不变量、界、幂等）。
**警告：生成出来的 oracle 会"发明规格"。** 实测：缺少规格约束时，测试把规范外的输入当成必须报错（假警报 **33%**，有规格的对照组 **0%**）；属性生成器召回了 30 个缺陷中的 28 个，但同时**发明了规格外要求**（[arXiv 2607.06636](https://arxiv.org/abs/2607.06636)）。
所以：先钉死**规格**再生成；对"生成器自己编出来的期望"单独 review —— 假警报会让门禁被忽略，和漏检一样有害。

### 6.8 变异自检（L7）——每条判据的入场券
```
基线：干净数据上必须 PASS
变异：注入一个"已知应该被发现"的缺陷（改值 / 删行 / 改挂父对象 / 换 payload）
期望：判据变红
```
- **逐个独立注入 + 回滚**，别一次改三处。
- 变异点覆盖**每一类**你声称能发现的问题（缺 / 多 / 值不同 / 挂错）。
- 固化成 `--self-test` 进仓库；口头"我试过会红"不算。
- 自检本身也要能红：去掉变异，自检应该 FAIL（否则你在自证）。

### 6.9 独立性机械校验（元判据）
防：判据悄悄 import 了被测模块。
```
解析判据源文件的 import 列表，断言不含生产包前缀（kb. / chunker / app.）
用 AST，别用 grep（注释和字符串会骗你）
```
做成**对每个判据文件都跑**的元判据，接进门禁。

### 6.10 时间与快照纪律
- 对账绑定**同一轮构建 / 同一批产物**：把产物指纹（hash / run_id / 版本）写进输出。
- 跨轮次差异报 **stale（环境漂移）**，不要报 defect，否则判据被当噪音。
- 失败**留档**：原始输出 + 产物指纹 + 判据版本。

## 7. 门禁清单

一次性的"我查过了"不算门禁。**门禁 = 会自己跑、会非零退出、别人改不动的东西。**

**G0 先证明这道门会拦**——接线完成第一件事：故意让它红一次（临时接一个必然失败的判据），期望整条构建非零退出。还是 0 → 接线是假的。

**G1 判据独立性：机械校验**——每个判据文件过 AST import 检查；这条本身也进同一个门禁。

**G2 判据受保护**——以下改动等同修改验收标准，必须留痕 + 复核：放宽比较（阈值 / 容差 / 集合 vs 多重集）、删 / skip / xfail 断言、扩大排除集、收窄输入生成域、更新快照 / fixture。排除项要在输出里**打印原因和数量**，不许静默。

**G3 声明登记表（claims → check）**——维护 `claim_id → 判据` 的机读登记；文档里每条能被判定的声明都要挂一个；没挂的标 `UNVERIFIED` 不许当结论。加强版：新声明没挂判据就让构建失败。**一次性计数不算判据**（今天成立的 `153→112`、`<12=0`，明天入库更多文档就不成立）。

**G4 严重度**——`error`（不变量被破坏：缺 / 多 / 挂错 / 值不同）→ 非零退出；`warning`（可疑：未登记类型、分布异常、多宿主）→ 打印 + 计数，不拦。warning 必须有数、可见；每出现新类型，决定"补登记→升级为 error"或"明确接受"。

**G5 豁免：具名、限时、写补偿控制**——`{判据, 原因, 责任人, 到期时间, 补偿控制, 残余风险}`，never silently。无到期时间 = 永久放水；到期后自动恢复 error。

**G6 证据包**——命令 + exit code + 原始输出（完整版）+ 产物指纹 + 判据版本（commit）+ 该轮其它判据情况。构建报告里带 `acceptance: {passed, oracles:[{name,status,exit_code,tail}]}` 是好起点。

**G7 不给没有依据的阈值**——不设默认通过线（"命中率必须 ≥ X%"），阈值无证据基础且诱发 Goodhart（分数可用"补测试"或"宣称等价"刷高，只有一条免费）。门禁看**"有没有存活的问题"**，不看百分比。本地下限必须写明依据并单独 review。

**G8 接线方式**——判据**以独立进程运行**，用 exit code 当判据（别塞进构建进程，异常会被吞、也没法单独复跑）；默认**开**，给逃生口但要在报告里留痕；依赖缺失的判据要**显式 skip 并标注原因**，不要假装 PASS。

## 8. FAIL 归因与修复纪律

判据变红只有三种可能，**必须先分类再动手**。跳过分类直接改代码 / 改判据，是漏检和假修的根源。

| 分类 | 症状 | 处理 |
|---|---|---|
| **产品缺陷** | 产物确实错了（缺、多、挂错、值不同） | 修产品；判据保持不动，修完必须变绿 |
| **判据缺陷** | 产物是对的，判据取错了对象 / 漏了分支 / 口径与产品不一致 | 修判据，且按同样标准证明修好（先红后绿） |
| **环境漂移** | 两边产物不属于同一轮次 / 数据被并发改动 | 复位环境或绑定快照重跑；报 `stale`，不要报 defect |

**关键**：允许把判据改成"正确测量产品真实行为"；**不允许**把判据改成"不再报警"。判断标准一句话：

> 修完之后，**原先那个"已知缺陷"注进去还应该红**（L7 自检仍成立）。让自检失效的修法就是放水。

**两条纪律**
1. **非破坏性**：批量重算判据数据时，失败项**保留原值并标记**，不要静默覆盖成空（一次覆盖会让旧数据永远找不回来）。
2. **先红后绿的顺序不能反**：先让新判据在已知缺陷上变红，再让它对干净数据变绿。

**报告纪律**：未成功不得声称通过；写清**已验什么 / 没验什么 / 残余风险 / 哪些是 UNVERIFIED**；排除项必须报出数量与原因，不许藏在分母里。

## 9. 反模式

- 先去重成集合再比 → 丢掉数量
- 取并集 → 掩盖单边缺失
- 有代理主键却以为有自然唯一键
- 拿产物跟它的上游对 → 同源自洽，必然一致
- 判据 import 了它要检查的那个模块
- 让 AI 评审判据 / 让 AI 评审 AI
- 只查「是不是 NULL」，不查「是不是对」
- 把「没报错」当「没问题」
- 判据停在 L1 / L2 就写进门禁
- 判据用**非 L7** 的方式"证明"自己有效（只跑一遍看着是绿的）
- 用"未判定条目不进分母"掩盖缺针 → 要么补针，要么把排除数和原因**报出来**
- 给门禁设没有依据的百分比阈值
- **拿二手转述当证据**（聚合仓库 / 博客 / 别人的总结）→ 回原始出处核；核不到就标"未验证"
- 把**覆盖率 / 变异分当质量指标或门禁阈值**
- **把规则当定理用**（不看它的适用条件就照搬，例如"skill 要拆文件"）→ 先问"这条规则的触发条件成立吗"

## 10. 工作流

1. 列出所有**产物对**（A, B）。
2. 每对从 L1 往上写到 **L3+**。
3. 把文档 / 报告里**每条能被判定的声明**找一条判据对应。
4. 找不到判据的声明 → 标 `UNVERIFIED`，不许当结论留着。
5. 每条先证明它会红（L7），再把"会红"固化成自检。
6. **FAIL 必须归因**（§8 三分类），判据缺陷按同样标准修，**不得靠放宽判据了事**。
7. 维护 `声明 → 判据` 登记；新声明没挂判据不许当结论。
8. 门禁化：接进构建 / CI，失败**非零退出**；可给逃生口，但**默认开**。接线后先做 G0（证明会拦）。

## 11. 实例（本仓真实）

**A. 引用计数（本 skill 的起点）**：文档里引用出现 155 次，边表只有 117 行 → 缺 38 条，门禁却报 PASS。
- 原判据失效：`internal_truth - captured` 两边都是 `Set`，且 `captured` 取了并集 → 去重丢数量、并集掩盖缺边。
- 修正：按 doc 分组、按 `(token,anchor,kind)` **逐条计数对齐** → 立刻 FAIL。
- **教训：漏检的原因通常是判据停在 L1，不是 AI 不够多。**

**B. 判据自己 import 了被测模块**：召回评测脚本 `import` 了生产检索器，还用生产的文本构造函数重建比对串 → 同源自洽；且比的是"命中块文本"，而产品交付的是"整节文本"，**测错了对象**。修法：拆成「跑产品的采集」+「零生产导入的纯裁判」，针改成纯内容并要求在**交付物**里唯一。
- **教训：判据的 import 清单要机械校验，不能靠自觉。**

**C. 判据自身的缺陷被误当成产品缺陷**：新判据首跑报 1 处不一致，追查是**判据漏处理某种元素类型**（文档提及 `mention_doc`），不是产品错。
- 正确修法：按元素规范**独立**补齐分支（仍不 import 生产解析器）。错误修法：把文本比较降级成 warning —— 那样再也发现不了真正的挂错。
- **教训：FAIL 必须三分类归因；"放宽比较让它变绿"不是修复，是自欺。**

**D. 拿二手转述当证据**：本 skill 起草时引了一个 0 star 聚合仓库的数字。核查后数字本身正确（有三个原始论文支撑），但**引用方式错了** —— 该核原始论文。
- **教训：低关注度来源 ≠ 内容错误，但必须回原始出处核；核不到就标"未验证"。**
